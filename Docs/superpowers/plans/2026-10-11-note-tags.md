# Lightweight Note Tags Implementation Plan

**Goal:** Create tags with inline hashtags and browse notes grouped by tag.
**Architecture:** Derive tags from Markdown; cache them in existing Rust metadata. Reuse current note save/event flows and add a separate tag browser beside category mode.
**Tech Stack:** React, TypeScript, Rust, Tauri, Vitest. No new dependencies.
**Spec:** `docs/plans/2026-10-11-note-tags-design.md`

## Global Constraints

- All files use UTF-8; follow existing app directories.
- Tags remain part of Markdown; old metadata stays compatible.
- Existing category operations keep their semantics.

## Review Focus

- Markdown headings, code, URLs and escapes must not create tags.
- Old notes with tags beyond the preview need complete extraction.
- Multi-tag notes appear once per tag and untagged notes remain reachable.
- Removing the last tag must survive saving and reopening.
- Grouped browsing must preserve search, selection and note context menus.
